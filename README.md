# 採集記録アプリ (collector-app)

生物採集時の座標（十進数）・標高・時刻・サンプルIDをオフラインで記録し、
オンライン復帰時にGoogleスプレッドシートへ自動同期するPWA（Progressive Web App）です。
iPhone / Androidどちらでもホーム画面に追加してアプリのように使えます。運用費は無料です。

## できること

- 記録ボタンを1タップで、ID・座標（十進数）・標高・時刻を保存
- オフラインでも記録可能。オンラインに戻ったら自動でGoogleスプレッドシートへ同期
- コロニー採集など特別な採集をワンタッチで区別（IDの末尾に文字を追加）。この「タグ」は「設定」タブで自由に追加・削除できる
- メモ（備考）を任意で入力
- 記録済みデータの一覧表示・後からの編集（メモ追記、ID修正など）
- 押し間違い防止のため、「直前の1件を取り消す」には確認ポップアップが入る
- GPSの取得精度（誤差半径）を色（緑/黄/赤）で表示

## 2. Googleスプレッドシートへの同期を設定する（任意）

同期機能を使うと、記録したデータが自動でGoogleスプレッドシートにも保存されます。
使わなくてもアプリ単体の記録・閲覧・編集・CSV書き出しは可能です。完全無料で行えます。

### 2-1. スプレッドシートを新規作成する

1. [Google スプレッドシート](https://sheets.google.com) を開き、新しいスプレッドシートを作成する。
2. わかりやすい名前（例:「採集記録」）を付ける。

### 2-2. Apps Script エディタを開く

1. スプレッドシートのメニューから「拡張機能」→「Apps Script」を選択する。
2. デフォルトで開かれる `コード.gs`（または `Code.gs`）の内容を全て削除し、
   このフォルダの `gas/Code.gs` の内容を貼り付ける。
3. 上部の「保存」（フロッピーディスクのアイコン）をクリックする。

### 2-3. ウェブアプリとしてデプロイする

1. 右上の「デプロイ」→「新しいデプロイ」をクリックする。
2. 「種類の選択」（歯車アイコン）から「ウェブアプリ」を選択する。
3. 設定:
   - 説明: 任意（例: 採集記録sync v1）
   - 次のユーザーとして実行: **自分**
   - アクセスできるユーザー: **全員**
     （「全員」を選んでも、URLを知っている人以外はアクセスできません。
     これはPWA側から認証なしでPOSTするために必要な設定です。）
4. 「デプロイ」をクリックする。
5. 初回は「承認が必要です」という画面が出ます。自分のGoogleアカウントを選び、
   「詳細」→「（プロジェクト名）に移動」→「許可」と進めてください
   （これは自作スクリプトなので安全です。Googleの警告は未検証アプリに対する
   標準的な確認です）。
6. デプロイ完了後に表示される **ウェブアプリのURL**（
   `https://script.google.com/macros/s/xxxxxxxx/exec` の形式）をコピーする。

### 2-4. アプリ側にURLを登録する

1. 採集記録アプリを開き、「設定」タブへ移動する。
2. 「Google スプレッドシート同期」の入力欄に、コピーしたURLを貼り付けて保存する。
3. 「一覧」タブの「今すぐ同期」を押して、正常に同期できるか確認する。
   スプレッドシートに `records` シートが自動作成され、そこに行が追加されていれば成功です。

### 2-5. コードを更新したときの再デプロイについて

`Code.gs` の内容を変更した場合、保存するだけでは反映されません。
「デプロイ」→「デプロイを管理」→ 既存のデプロイの鉛筆アイコン →
「バージョン」を「新バージョン」に変更 → 「デプロイ」を再度実行してください。
（URLは変わらないので、アプリ側の設定変更は不要です。)

### 2-6. 仕様メモ

- 受信したレコードは `sample_id` をキーに重複チェックを行い、既に同じIDの行が
  あれば上書き更新、なければ新規追加します。これにより、アプリ側で記録後に
  ID・メモ・タグを編集した場合の再送信にも対応します。
- ヘッダー行は `records` シート作成時に自動で挿入されます。列を並べ替えたり
  削除したりすると同期が壊れるため、列の追加は右側に対してのみ行ってください。
- 位置情報の列（`lat`, `lon`）は十進数（度）です。Googleマップ等にそのまま
  貼り付けて確認できます。

## 3. 使い方

1. アプリを開くと自動的にGPSの取得が始まります。画面上部に緯度・経度・
   標高・**取得精度（誤差半径）**が表示され、精度に応じて緑（良好）/黄（普通）/
   赤（低精度）で色分けされます。
2. コロニーなど特別な採集をした場合は、対応するタグボタンをタップしてから
   記録してください（IDの末尾に自動で文字が付きます）。タグは「設定」タブの
   「タグ設定」で自由に追加・削除できます（表示する名前と、IDの末尾に付ける
   1〜4文字を入力するだけです）。
3. 必要であればメモを入力し、「記録する」を押します。振動でフィードバックがあります。
4. 押し間違えた場合は「直前の1件を取り消す」で取り消せます。誤操作防止のため、
   取り消す前に確認ポップアップが表示されます。
5. 「一覧」タブで記録済みデータを確認・編集できます。行をタップすると
   ID・座標・タグ・メモを編集できるモーダルが開きます。
6. オンラインになると自動的にGoogleスプレッドシートへ同期されます。
   手動で同期したい場合は「一覧」タブの「今すぐ同期」を押してください。
7. 「設定」タブでは、タグの追加・削除、採集日の手動固定（深夜をまたぐ採集向け）、
   同期先URLの設定、全データのJSONバックアップ・インポートができます。

## 4. 既知の制約と運用上の注意

- **バックグラウンド位置取得は行いません。** アプリを開いている間のみGPSを
  取得します。ホーム画面に戻したり画面をロックすると、次に開いたときに
  再度精度が安定するまで少し時間がかかることがあります。
- **iOSのSafari/PWAの制約により、画面を閉じた状態での位置情報取得はできません。**
  これは意図的な設計であり、常時追跡による電池消費を避けるためのものです。
- ブラウザのローカルストレージ（IndexedDB）は、端末のストレージが極端に
  逼迫した場合にOSにより削除されるリスクがあります。定期的に
  「設定」タブの「全データをJSONでエクスポート」でバックアップを取るか、
  Googleスプレッドシートへの同期を確実に行ってください。
- GPS精度が悪い場所（谷間・密林・室内等）では、必要に応じて一覧の編集モーダルから
  座標を手動修正できます。
- 複数人での採集を想定する場合、ID重複を避けるため採集者イニシャルなどを
  タグとして追加することをお勧めします。
- 同期データはスプレッドシートの元々のシート（`シート1`など）ではなく、
  自動生成される `records` という専用シートに書き込まれます。
- **公開URLはリンクを知っている人なら誰でも使えます。** GitHub Pagesで公開すると、
  そのURLにアクセスした人は誰でもアプリを開いて「ホーム画面に追加」でき、記録機能を
  使えます（ログインは不要です）。ただし各人の記録データはそれぞれの端末のブラウザ内
  （IndexedDB）に保存されるだけで、自動的には共有されません。全員のデータを1つの
  スプレッドシートに集めたい場合は、同じGASのウェブアプリURLを各自の「設定」タブに
  登録してもらう必要があります（逆に、個別にデータを管理したい場合は、各自で
  別々のスプレッドシートを用意するか、同期機能自体を使わなくても構いません）。

## 5. 自分専用の独立したコピーを公開する（任意・GitHubの知識が必要）

「1. 今すぐ使ってみる」のURLをそのまま使う代わりに、コードを改造したい、
または元の公開者のリポジトリに依存しない自分専用の別URLで公開したい場合の
手順です。このフォルダには、公開・配布に必要な全てのファイルが入っています。
**このフォルダの中身をそのままGitHubにアップロードするだけで、自分専用のアプリを公開できます。**

### 5-1. 必要なもの

- GitHubアカウント（無料）
- Googleアカウント（Googleスプレッドシートへの同期を使う場合。無料）
- iPhoneまたはAndroid端末

作業はすべてパソコンのブラウザで行います。

### 5-2. GitHubアカウントを作る

1. https://github.com/ を開き、右上の「Sign up」から新しいアカウントを作成する。
   メールアドレス・パスワード・ユーザー名を設定し、画面の指示に従って進める
   （メール認証が必要です）。
2. ログインできたら準備完了です。

### 5-3. リポジトリを作る

1. GitHubにログインした状態で、右上の「+」→「New repository」をクリックする。
2. 「Repository name」に好きな名前を入力する（例: `collector-app`）。
3. 「Public」または「Private」はどちらでも構いません
   （Privateでも、後述のGitHub Pagesの公開設定自体は可能です。ただしGitHub Pagesで
   公開したページ自体はURLを知っている人なら誰でも見られる点に注意してください）。
4. 「Add a README file」はチェックを入れたままで構いません。
5. 「Create repository」をクリックする。

### 5-4. ファイルをアップロードする

**重要: このフォルダ（`collector-app` のような名前）自体をアップロードするのではなく、
このフォルダの「中身」（`index.html`, `app.js`, `icons/` フォルダなど）を
リポジトリの直下に配置してください。** フォルダをもう1段掘った状態
（`リポジトリ/collector-app/index.html` のような構成）になると、後述の
GitHub Pages設定で正しく公開されません。

1. 作成したリポジトリのページを開く。
2. 「Add file」→「Upload files」をクリックする。
3. パソコンでこのフォルダを開き、**中に入っているファイル・フォルダを全て選択**
   （`index.html`, `app.js`, `db.js`, `idlogic.js`, `sync.js`, `style.css`,
   `manifest.json`, `service-worker.js`, `icons/`, `gas/`, `test/`, `README.md`）してから、
   ブラウザの画面にまとめてドラッグ&ドロップする。
4. 下にスクロールして「Commit changes」をクリックする。
5. アップロード後、リポジトリのファイル一覧が本フォルダと同じ構成
   （`index.html` などがリポジトリの一番上の階層に見える状態）になっていることを確認する。

### 5-5. GitHub Pagesで公開する

1. リポジトリページの上部タブから「Settings」を開く。
2. 左側メニューの「Pages」をクリックする。
3. 「Build and deployment」の「Source」で「Deploy from a branch」を選択する。
4. 「Branch」で `main`（または `master`）を選び、フォルダは **`/ (root)`** を選択して
   「Save」をクリックする。
5. 数十秒〜数分待つと、ページ上部に
   `Your site is live at https://ユーザー名.github.io/リポジトリ名/` という
   URLが表示される。これが公開URLです。

このURLを開いて、記録画面が表示されれば公開成功です。

#### 更新するとき

ファイルを修正した場合は、同じ「Add file」→「Upload files」で該当ファイルを
再アップロードして「Commit changes」するだけで反映されます（Pagesの設定を
やり直す必要はありません。数分で反映されます）。

### 5-6. スマートフォンにインストールする

「1. 今すぐ使ってみる」のiPhone（Safari）/ Android（Chrome）の手順と同じですが、
URLは上記で確認した**自分の公開URL**に読み替えてください。

## 7. テストの実行方法（開発者向け・任意）

アプリの動作を変更しない限り、この手順は不要です。コードを改造する場合の
動作確認用です。[Node.js](https://nodejs.org/)がインストールされたパソコンで:

```bash
cd test
npm install     # jsdom, fake-indexeddb をインストール（初回のみ）
npm test        # 全テスト（計62件）を実行
```

個別に実行する場合:

```bash
node test_idlogic.js                    # ID採番ロジックの単体テスト (16件)
node integration_test.js                # 記録・取り消しフローの統合テスト (18件)
node integration_test_list_edit.js      # 一覧・編集・タグ設定の統合テスト (18件)
node integration_test_sync.js           # 同期キューの統合テスト (10件)
```
