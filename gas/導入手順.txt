座標記録アプリ改良版と住所補完ツール（2026-11-18）

このフォルダには、改良した記録アプリと、スプレッドシートで動く住所補完ツールが入っています。
Dropbox内のファイルを書き換えるだけでは、公開済みのiPhoneアプリやGoogle側には反映されません。

■ iPhoneの初回設定：位置情報を許可する
1. Safariで使用するアプリのURL（通常 https://formica-kk.github.io/ ）を開きます。
   初回の位置情報ポップアップでは「許可」を選びます。
2. アドレスバーのページメニュー（必要に応じて「…」）→「Webサイトの設定」を開きます。
3. 「位置情報」を「許可」に変更します。
   ポップアップで許可したあとも毎回確認される場合は、このサイト設定を行ってください。
4. 初めて導入する場合は、共有ボタン（□に↑）→「ホーム画面に追加」を選びます。
   追加済みの場合は再追加せず、そのままホーム画面のアプリを閉じて開き直します。
5. GPSは自動で取得されます。開き直した際に確認が出ず取得できることを確認してください。

Safariで設定するURLは、ホーム画面のアプリと同じものにしてください。
iOS 26.6.2では、この設定でホーム画面から開き直した際の再確認が出なくなったことを
利用者の実機で確認しています。表示名はiOSによって異なる場合があります。
取得できない場合は、iPhoneの「設定」→「プライバシーとセキュリティ」→「位置情報サービス」で
「SafariのWebサイト」を「このアプリの使用中」に設定し、「正確な位置情報」もオンにします。
この設定のためにアプリを削除したり、SafariのWebサイトデータを消去したりする必要はありません。
同じ説明はアプリ内の「設定」にもあります。

■ 住所の出力
国                  都道府県     市区町村・町域
日本                東京都       千代田区丸の内
日本                大阪府       大阪市北区西天満
（上記は表示例です）

丁目・番地・郵便番号・建物名は省略します。海外は州・県に相当する名称を「都道府県」に入れます。
取得できない項目は空欄にし、住所補完_状態に「一部取得」「住所なし」などを表示します。
山中や行政界の近くではGoogleの推定住所を確認してください。

■ 住所補完を導入する（パソコンで初回のみ）
1. 普段使っている「採集記録」スプレッドシートを、編集できるアカウントで開きます。
2. 「拡張機能」→「Apps Script」を開きます。
3. 既存のコード.gsは残します。「＋」→「スクリプト」で AddressAssistant を追加し、
   gas/AddressAssistant.gs の内容をすべて貼り付けます。
4. 「＋」→「HTML」で AddressSidebar を追加し、
   gas/AddressSidebar.html の内容をすべて貼り付けます。
   ファイル名は大文字・小文字も含めて合わせてください。
5. 保存します。既に onOpen がある場合は新しい onOpen を重複させず、
   その中のメニュー追加処理を既存の onOpen に統合してください。
6. スプレッドシートを再読み込みします。
7. 上部の「住所補完」→「住所補完を開く」を選びます。
   初回はGoogleの承認画面が表示されます。操作するシート・スクリプトが自分のものと確認し、
   必要な権限を確認して承認してください。
8. 「まず5件をプレビュー」で、住所が希望の分け方になっているか確認します。
9. 「空欄に住所を入れる」で過去の記録を処理します。
   サイドバーを開いたまま待ちます。停止ボタンは現在の最大30件の処理後に停止します。
10. 必要なら「自動補完をオンにする」を押します。
    以降は1時間ごとに最大30件を処理し、残りがあれば次の実行に持ち越します。
    iPhoneやパソコンでアプリを開いておく必要はありません。
    Googleスプレッドシートのスマートフォンアプリではサイドバー操作ができないため、初回設定はPCで行います。

住所補完だけの導入では、ウェブアプリの新規デプロイや公開範囲の変更は不要です。
住所補完用にAPIキーを入力する必要もありません。GAS標準のMapsサービスを利用します。
補完対象の緯度・経度をGoogleへ送信します。端末内の未同期データは処理されません。

初回の書き込み時に、右端に以下を追加します。
・国
・都道府県
・市区町村・町域
・住所補完_状態
・住所補完_座標（非表示。座標変更の検出に使用）

入力済みの住所や数式は上書きしません。
座標が変わった行に住所がある場合は「座標変更・要確認」とし、元の住所を残します。
再取得する場合は、その行の住所3列と住所補完_状態を空欄にしてから実行してください。
「住所なし」や「一部取得」を再検索するときも同じです。
元の先頭12列は既存の同期処理が使用するので、移動・削除・名前変更を避けてください。
処理中のシートの並べ替え・編集は避けてください。

Googleの実行時間・日次割当を超えるとエラーが表示されます。書き込み済みの行は保持されます。
時間をおいて再実行してください。自動補完は1時間30件に制限していますが、プレビューや手動実行、
同じアカウントの他スクリプトの利用分も割当に含まれます。

■ 記録アプリを改良版に更新する
1. iPhoneの現在のアプリで、「設定」→「全データをJSONでエクスポート」を実行し、保存します。
2. 現在のGitHub Pagesリポジトリに、collector-app の公開用ファイルを上書きします。
   index.html / app.js / gps.js / db.js / sync.js / style.css / service-worker.js
   gps.js は今回新しく追加するファイルです。その他の manifest.json・icons・idlogic.js は維持します。
   現在の公開URLと同じ場所に配置してください。URLが変わると端末内データの保存場所も変わります。
3. Pagesの更新完了後、オンラインでiPhoneのアプリを開き、一度閉じて開き直します。
   更新が見えない場合はさらに開き直してください。
4. GPSの開始ボタンがなく、起動時に自動で位置情報を取得すれば今回の更新版です。
   アプリ削除やSafariのWebサイトデータ消去は、更新手段として行わないでください。

改良内容
・GPSの開始ボタンを廃止し、起動時に自動で位置情報を取得します。
・画面を閉じるとGPSを停止し、画面に戻ると自動で再開します。
・15秒より古い座標をそのまま記録しません。取得を待ち、25秒で取得できなければ保存せず知らせます。
・連打による二重記録を防止します。
・同期中にメモ等を編集しても、古い同期結果で編集内容を上書きしません。
・同期中に削除したローカル記録が復活しないようにしました。
・起動時／画面に戻ったときにも未同期分を送信します。
・標高の誤差が不明なときに「±0m」と誤表示しません。

同期サーバーの競合対策も入れる場合
Google Apps Scriptの既存の Code.gs を、gas/Code.gs の内容に更新し、
「デプロイ」→「デプロイを管理」→既存デプロイの編集→「新バージョン」→「デプロイ」を行います。
既存デプロイを更新すればURLは変わりません。新規デプロイは不要です。
住所補完処理と記録受信処理が同時に書き込むことを、同じスクリプトのロックで防ぎます。
既存Code.gsに独自の変更がある場合は丸ごと置き換えず、差分を確認してください。

■ 元からある仕様で、今回も残るもの
・記録を削除／取り消しても、既に送信済みのスプレッドシートの行は削除されません。
・同期済みのsample_idを変更すると、新しいIDの行として送信され、元のIDの行はシートに残ります。
・住所はスプレッドシート側だけに保存され、iPhone内の記録やCSVには逆同期しません。

■ 検証
test フォルダで npm install のあと npm test を実行すると、98件の自動テストで検証できます。
iOS 26.6.2のサイト許可設定の効果は利用者の実機で確認済みです。GPS精度は利用環境で確認してください。
